PhoneLab スマホが実験器具。AI は答えを言わない。— 2026-10-09 時点で動いている範囲だけを描いた図

生徒が予想を書く → ラボ先生（Gemini）が予想を壊せる実験をカタログから選ぶ → 端末のセンサーで測る → 機械が検査して怪しければ保留 → 結果を読んで次の一手 → 先生は学級を一目で見て、ラボ先生の見立てを聞き、必要なら全端末を止める

生徒の端末（Web アプリ、学校の iPad ／ 家のスマホ）

予想ゲート

「こうなると思う」を書くまで、実験もヒントもセンサーも出ない。理由が無ければラボ先生が 1 回だけ問い返す

端末内の測定と検査（生データは端末の外に出ない）

DeviceMotion（加速度・ジャイロ）／ Web Audio（マイク）を、承認した実験の秒数だけ読む

  • 二本の時計: ジャイロ ω×L と 加速度 √((|a|−g)L)、基本周波数と倍音
  • 検査: 欠測・飽和・雑音・二系統不一致 → 保留（結論を出さない）
  • 3, 2, 1 の合図、測り直し（3 回まで）、3 回の平均
加速度ジャイロマイク位置情報は永久に不要

記録（localStorage）と、先生に送る要約

予想・計画・許可・測定の特徴量・検査・判定・次の予測・ラボ先生との会話を一本に。先生へは 要約だけ（波形・音声は送らない）

教員画面（PC、学級コード＋教師 PIN）

予想の向きの分布 → いま見に行く子 → ラボ先生の見立て（3 行・見に行く順） → 全員の表（番号だけ、記録の「判断」の行と Cloud Trace へのリンク） → 許可・家でやる実験 → 全端末停止（先生の操作は「操作の記録」に残る）

POST /api/plan（予想・候補の id・学級コード）
POST /api/replan・/api/next（保留・結果のあと）
POST /api/chat（考えを書いてから）
POST /api/records（要約）
GET /api/class（2 秒ごと、halted）
POST /api/class/…/halt・policy・insight（PIN）

Cloud Run（asia-northeast1）— FastAPI ＋ Google ADK 2.8

決定論の Policy（LLM は読まない）

禁止動作（落とす・高所・水・交通）／メモ内の指示（「検査を飛ばして」）／答えの要求 → モデルを呼ばずに却下・問い返し。却下は理由 3 つ＋代替実験

ラボ先生 = 5 つの LlmAgent（Gemini 3.5 Flash-Lite。4 つは構造化出力、Tutor は文章）

  • Planner: 予想を読み、残りの候補から実験を 1 つ選ぶ。答え（answers.py）は渡さない
  • Replanner: 保留の理由を読み、直して測り直す／別の実験へ（条件の値は変えさせない）
  • NextStep: 結果を読み、次に確かめる実験と次の予想の問いかけ（ループを閉じる）
  • ClassAgent: ツール 2 つ（読み取り専用）で学級を読み、先生に 3 行。操作はしない
  • Tutor: ふり返り。説明は自分の考えを書いてから

統制層 PolicyPlugin（ADK BasePlugin、Runner に一度登録）

before_run

先生が学級を止めていれば、エージェントを走らせない

before_model

Model Armor で生徒の文を検査。回数上限ならモデルを呼ばない。温度・思考量を強制

before_tool

許したツールだけ、4 回まで、学級にいる番号だけ

after_model

候補外・結果の言葉・条件を変える助言・危ない動作の勧め・説明の漏えい・停止の勧めを検査。落ちたら理由を返して 1 回作り直させる

学級と記録（サーバは要約だけを持つ）

classes/{code}: 許可センサー・家でやる実験・halted・PIN のハッシュ　students/{no}: いまの記録の要約　records/{id}: 履歴

レート制限（接続元ごと）、12 秒 / 25 秒でタイムアウト、停止中は 409

generate_content（構造化出力）
OTLP（本文は送らない）
classes / students / records
gcloud run deploy --source

Google Cloud

Vertex AI — Gemini 3.5 Flash-Lite

5 つのエージェント。計画まで中央値 1〜3 秒、授業 1 回 Gemini 約 30 円の試算（docs/eval.md）

Model Armor（us-central1）

テンプレート phonelab-student: 注入・脱獄・有害表現。東京には多言語の検出が無いため us-central1。予想・会話の履歴も含めて検査し、検査できないときは AI に渡さず決まりごとで進める

Cloud Trace（Telemetry API）

phonelab.plan → invoke_agent → phonelab.model_armor → call_llm → phonelab.policy → phonelab.self_correct。生徒の文は記録しない。同じ段を「判断の跡」として画面にも出す

Firestore（native、asia-northeast1）

学級・生徒・記録の要約、回数の枠（トランザクション）、PIN の間違いの数、先生の操作の記録。クライアント SDK は使わず、API 経由だけ

Cloud Build → Cloud Run

ソースデプロイ（Dockerfile が Web もビルド）。min-instances 0。実行は専用の最小権限サービスアカウント（役割 4 つ）、秘密は Secret Manager

LLM が判断すること: 予想の読み取りと実験の選択、保留と結果のあとの次の一手、学級の見立て、ふり返りの問い返し LLM が触れないこと: 安全の判定、測定の検査、判定文、停止、学級の設定の変更 未実装（設計のみ）: サーバ側 Verifier と Cloud KMS 署名、見立ての提案を承認して反映する UI。注: 停止中も学級の見立て（読み取りだけ）は動く。自己修正は Planner・Replanner・NextStep
