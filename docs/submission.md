## プロジェクト概要（200〜300 字）

<!-- overview -->
中学校の理科で、生徒の端末を実験器具にするエージェントです。生徒が「強くはじくと音が高くなると思う」と予想を書くと、AI のラボ先生（Gemini）が答えを言わずに、その予想を確かめられる実験を選びます。生徒が承認するとマイクや加速度センサーで測り、機械が二通りの測り方の一致を検査して、怪しければ結論を保留します。結果を読んだラボ先生は次に確かめることを選び、次の予想を促します。先生は学級を一画面で見て、全端末を止められます。
<!-- /overview -->

## 課題と解決（800 字まで）

<!-- problem -->
**課題: 理科の実験が「予想を確かめる場」になりにくい**
- 観察・実験を週 1 回以上行う中学校は 48.5%（令和 7 年度 全国学力・学習状況調査）。実験助手がいるのは小中学校の約 9%（2,649 / 29,563 校）で、多くの先生は準備から片付け、30 人の巡視まで一人で担います
- 測定アプリは「何を測れば自分の予想を確かめられるか」を教えず、怪しいデータも止めません。生成 AI に聞けば答えが先に出て、実験はただの答え合わせになります

**解決: AI は答えを言わず、予想を本物の測定で確かめさせる**
- 端末が実験器具。器具を買わずに、学校の iPad のマイクや加速度センサーで、音の高さや振り子の速さを測ります
- ラボ先生（Gemini）は予想を読み、確かめられる実験を選ぶだけ。理由の無い予想には問い返します
- 測定は機械が検査し、怪しければ「保留」。保留ならラボ先生が測り直し方を提案し、結果が出たら次に確かめることを選びます。判断と解釈はいつも生徒
- 先生は予想の分布と「いま見に行く子」を一画面で見て、ラボ先生に学級の見立てを聞き、全端末の測定を 1 タップで止められます（31 人で中央値 1.5 秒）

**エージェントを管理する仕組み**
- 統制層が 5 つのエージェントの入口と出口を検査します（Model Armor、危ない実験の却下、答えや危ない動作の差し替え、回数の上限）。注入・禁止動作 20 件を流した評価で、答えや結果が出力に出たのは 0 件でした

## アーキテクチャ説明（800 字まで）

<!-- architecture -->
**構成**: React の PWA（生徒の端末・教員画面）→ Cloud Run 上の FastAPI と Agent Development Kit（ADK）→ Vertex AI の Gemini 3.5 Flash-Lite。学級と記録の要約は Firestore、判断の跡は Cloud Trace。

**エージェント（ADK の LlmAgent × 5、すべて構造化出力）**
- Planner: 予想を読み、学級が許した候補から実験を選ぶ（答えは渡さない）
- Replanner: 保留の理由を読み、測り直しか別の実験を提案（実験の条件は変えさせない）
- NextStep: 結果を読み、次の実験か「先にふり返り」を選ぶ
- ClassAgent: 読み取り専用ツール 2 つで学級を読み、先生に見立てを伝える（操作はしない）
- Tutor: 説明は、生徒が自分の考えを書いてから

**設計の工夫**
- 統制層 PolicyPlugin（ADK の BasePlugin）: 停止の確認、Model Armor、回数の枠、ツールの制限、出力の検査。検査に落ちた出力は理由を返して 1 回作り直させる
- LLM が決めないこと: 測定の検査・判定・停止は決定論のコード。生データは端末から出さない
- 回数の枠は Firestore のトランザクションで、モデルを呼ぶ前に取る。先生の操作は監査記録に残す
- 最小権限: 専用のサービスアカウントに 4 つの役割だけ、秘密は Secret Manager
- 評価: 本物の Gemini で予想 30 件・注入 20 件を 3 回流し、別のモデルが漏えいを判定（78 件中 0 件）。Gemini の費用は授業 1 回 約 41 円（上限でも約 166 円）
<!-- /architecture -->

## プロジェクトイメージ（最大 10 枚、撮る候補）

1. 予想を書く画面と、ラボ先生の問い返し（吹き出し）
2. 計画の画面: 「何を何秒」の承認と「ラボ先生の判断の跡」
3. 測定の画面: 二通りの測り方（基本周波数と倍音）
4. 保留の画面: 保留の理由とラボ先生の測り直しの提案
5. 結果の画面: 「予想とちがった！」と次の一手
6. 教員画面: 予想の分布・いま見に行く子・ラボ先生の見立て
7. 教員画面: 全端末停止と「操作の記録」
8. 却下の画面: 「スマホを落として測りたい」→ 理由 3 つと代わりの実験
9. Cloud Trace: phonelab.policy → phonelab.self_correct のスパン
10. 実物の写真: 袋に入れた端末の振り子、輪ゴムをかけた箱
