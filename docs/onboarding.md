# 学校で使い始める手順

> 運用者（PhoneLab を動かす人）と先生が、授業の前にやること・授業中に困ったときにやること。
> 審査用の共用学級 `DEMO-2026` は README のとおり。ここは本物の学級を作るときの手順。

## 1. 運用者: 学級を発行する

```sh
cd app
GOOGLE_CLOUD_PROJECT=phonelab-2026 GOOGLE_CLOUD_QUOTA_PROJECT=phonelab-2026 \
uv run python -m scripts.create_class --school jhs --code 2A-SATO
```

- 出るのは **学級コード**（生徒に配る）と **先生の PIN**（6 桁。先生だけに渡す）の 2 つ
- PIN はこの画面に一度出るだけ。保存するのは塩つきのハッシュなので、運用者もあとから見られない
- `--code` を省くと `CLS-XXXXX` を作る。同じコードの学級がもうあれば作らない（上書きで記録を消さない）
- 高校は `--school hs`（振り子の周期など、高校のテーマが出る）

## 2. 先生: 授業の前（5 分）

1. `/teacher` を開き、学級コードと PIN を入れる。PIN が通ると 8 時間はセッションの印で入ったまま（授業中に PIN を入れ直さない）
2. **使ってよいセンサー**（加速度・ジャイロ・マイク）を選ぶ。選んでいないセンサーのテーマは、生徒の端末で選べなくなる
3. 家でやらせたい実験があれば「家でやる実験」を有効にする
4. 生徒に学級コードを板書する。出席番号の書き方（例 `S-04`、英数字とハイフン 8 文字まで）を決めておく

## 3. 生徒: 最初の 1 回

1. 本番 URL を開き「学級と番号を入れる」→ 学級コードと出席番号 → 保存
2. **初めて入った端末に、6 文字の合言葉が大きく出る**。メモする（家の人に見せてもよい）。「メモした」で閉じる
3. 同じ番号で別の端末（家のスマホなど）から入るときは、その合言葉を入れる。合言葉は「他人の番号に記録を書けないようにする」ためのもの

## 4. 授業中に困ったとき

| 困ったこと | やること |
|---|---|
| 生徒が合言葉をなくした・端末を替えた | 教員画面でその子の行を押す →「この番号の合言葉をリセット」。次に入った端末に新しい合言葉が出る |
| 全員の測定をすぐ止めたい | 教員画面の「全端末の測定を止める」。測定中の端末は 2 秒ごとに確かめるので、2〜3 秒で止まる（負荷試験で 31 人中央値 1.5 秒・最大 2.1 秒）。解除するまで計画・測定・次の一手は進まない |
| PIN を何度も間違えた | 10 分間に 10 回まちがえると、正しい PIN でも 10 分入れない。待つか、すでに入っている先生の端末を使う |
| 先生が PIN をなくした | 運用者に頼む: `uv run python -m scripts.create_class --rotate-pin 2A-SATO`。新しい PIN が出て、前の PIN と先生のセッションの印はすべて使えなくなる |
| 「ラボ先生が混み合っています」と出る | 回数の上限（計画 5・次の一手 3・再計画 3・会話 10 / 実験）か、同じ端末からの呼び出しが多すぎる。端末は決まりごと（カタログの順）で先へ進めるので、授業は止まらない |
| 学校の Wi-Fi が切れた | 測定と判定は端末の中で動く。記録は端末に残り、つながったら 5 秒おきに送り直す |

## 5. 記録はどこにあるか

- **端末の中**: 予想・測定の値・判定・会話・判断の跡（生データの波形や音声は端末から出ない）
- **サーバ（Firestore）**: 教員画面が見る要約だけ。予想の文、状態、検査の結果、測定ごとの 2 つの値と落ちた検査、生データのハッシュ、ラボ先生の呼び出しのトレース id（段の名前つき）。名前は持たない（出席番号だけ）
- **Cloud Trace**: ラボ先生の判断の経路。生徒の文は入れない（文字数とハッシュだけ）
- 家のスマホで入っても、学校の端末の記録は出てこない（記録は端末ごと。先生の画面には両方届く）

## 6. 学期の終わり

```sh
uv run python -m scripts.create_class --delete 2A-SATO
```

学級・生徒・記録の要約・回数をまとめて消す。生徒の端末の記録は「生徒の情報」→「この端末の記録を消す」で消す。
