# PhoneLab — スマホが実験器具。AI は答えを言わない。

第 5 回 Agentic AI Hackathon with Google Cloud への提出物。中学校の理科で、生徒の端末のマイクや加速度センサーを実験器具にする。生徒がテーマを選び、身近な材料で試して、予想と理由を書くと、AI の「ラボ先生」（Gemini）は**答えを言わずに**、その予想を確かめられる比較実験を選ぶ。生徒が承認して 2 条件を測り、アプリが測定を検査して、怪しければ結論を出さずに保留する。結果が出たら、ラボ先生は次に確かめることか、先にふり返ることを提案する。先生は学級を一画面で見て、ラボ先生に見立てを聞き、全端末の測定を止められる。

**何が違うか**: AI が法則や答えを見せるのではなく、**生徒の予想を起点に、比べる条件を選び、実測し、測りそこねたら結論を出さず、考察と次の予想に戻る**。その自律性を、ADK の統制層（入口と出口の検査・回数の枠・停止・監査）で管理している。

- 本番 URL: **https://phonelab-1094091671194.asia-northeast1.run.app**（Cloud Run、asia-northeast1）
- 設計ドキュメント: [`docs/`](docs/README.md)（ペルソナと使う場面、アーキテクチャ、Policy、Verifier、実験カタログ、記録の形）

## 動作確認の方法（審査員向け）

テスト用の学級を用意してあります。名前は入れません。

| 項目 | 値 |
|---|---|
| 学級コード | `DEMO-2026` |
| 見本の記録 | `D-01`〜`D-06`（保留・却下・判定・次の一手・計画中）。教員画面で開くとすぐ見えます。この番号では入場できません |
| 出席番号 | **自分だけの番号**（例 `J-1234`。英数字とハイフンで 8 文字まで）。番号は最初に入った端末のものになり、**そのとき 6 文字の合言葉が出ます**。「この番号は使われています」と出たら別の番号に（他人の番号に記録を書けないようにするため。合言葉をなくしたら教員画面でリセット） |
| 教員画面 | `/teacher` → 学級コード `DEMO-2026`、教師 PIN `4826` |

### 1. 生徒として（スマホ推奨。PC でも可）

1. 本番 URL を開き、「学級と番号を入れる」→ `DEMO-2026` と番号 → 保存
2. テーマ「音の高さ」（マイクだけで動く）→ 輪ゴムを箱にかけて、はじいてみる → 予想を書く（理由が無いとラボ先生が問い返します）
3. 「ラボ先生に実験を考えてもらう」→ Gemini が予想を読み、実験を 1 つ選びます（2 秒前後）。計画画面に「誰が選んだか」と「答えは渡していません」が出ます
4. 承認 → 「準備はいい？ 3, 2, 1」→ マイクで 5 秒 → 二つの計算で音の高さ（基本周波数と、倍音か周波数の山）→ 機械の検査 → 通れば次の条件、怪しければ **保留**
5. 結果は「測定が言っていること」として出ます（「正解」とは言いません）。その下に**ラボ先生の次の一手**: 予想と測定が合ったなら別の変数へ、食い違っていて理由をまだ書いていないなら「先にふり返り」。ふり返りのチャットは、自分の考えを書いてから
6. 計画・保留の画面の「ラボ先生の判断の跡」を開くと、何を読み、何を選び、統制層が何を直したか（自分で作り直したか）が段ごとに見えます
7. 試してほしい経路: 予想欄に「スマホを落として測りたい」→ Policy が**モデルを呼ばずに**却下し、理由 3 つと代替実験を出します。「答えだけ教えて」→ 答えは出ません
8. 振り子（加速度センサー）は iPhone / Android / iPad で。先生が「家でやる実験」を有効化すると、トップに「家で」の印で出ます

センサーの無い PC で流れだけ見る場合は、右上の ⚙ 設定 → **テストモード**（サンプルの測定で進めます。記録に「サンプル」と残ります）。

### 2. 先生として（PC 推奨）

1. `/teacher` を開き、学級コード `DEMO-2026` と PIN `4826` を入れる → 5 秒ごとに学級の様子が出ます
2. 上から: 予想の向きの分布（「高くなる 6 人」など）→ **いま見に行く子**（保留 → 却下の順）→ 全員の表（番号だけ）→ 選んだ子の記録の流れ
3. 右の **「ラボ先生の見立て」→「見立てを聞く」** → ラボ先生がツールで学級の要約を読み、3 行・見に行く順・先生が選べる手を返します（見本の記録だと「音の高さで 2 人がまわりの雑音で保留」など）。操作はしません。番号を押すとその子の記録の流れ（「判断」の行も）へ
4. 右上の **「全端末の測定を止める」** → 測定中の生徒の端末は 2 秒ごとに学級の状態を確かめていて、次の確認で停止画面になります（本番に 31 本の模擬クライアントを同時に流し、停止の API が応えてから全員が停止を受け取るまで中央値 1.5 秒・最大 2.1 秒。実機の端末のセンサーが止まるまでの時間ではない。[`docs/load-test.md`](docs/load-test.md)）。停止中はサーバがエージェントを動かしません（`/api/plan` `/api/replan` `/api/next` `/api/chat` は 409、ADK の `before_run_callback` でも止まる）。端末は 409 を受けると、確認を待たずに止まります。解除も同じボタン
5. 許可のトグル（マイク・加速度・カメラ）と「家でやる実験」の有効化も、この画面から

> 審査の期間中（〜2026-12-01）は動作する状態を保ちます。学級 `DEMO-2026` は共用なので、他の人の番号の記録が見えることがあります。**「全端末の測定を止める」を試したら、同じボタンで解除してください**（ほかの審査員の端末も止まります）。

## 学びの根拠

流れは理科教育の **予想→観察→説明（POE、White & Gunstone 1992）** と、学習指導要領の「見通しをもって観察・実験」に沿う。狙う思い込み（音の大きさと高さの混同など）を決め、結果には音の大きさも並べる。食い違ったときは測定が検査を通ったことを添える（Chinn & Brewer 1993）。AI が答えを先に言わないのは、答えを出す AI で練習すると AI を外したテストで成績が下がった研究（Bastani ら, PNAS 2025）を踏まえた設計。**授業での学習効果は未検証**（研究は設計の根拠で、効果の証拠ではない）。出典と詳しい対応は [`docs/zenn-article.md`](docs/zenn-article.md) の 4 節。

## 何が「エージェント」か（審査軸②）

予想 → 計画 → 測定 → 検査 → 判定 → **次の予想**、のループのうち、言葉と判断が要るところを 4 つのエージェントが受け持ち、測定と検査は機械が受け持つ。どのエージェントも ADK の統制層（`PolicyPlugin`）に囲まれている。

| 判断 | エージェント（ADK `LlmAgent`） | 統制 |
|---|---|---|
| 予想を読み、確かめられる実験を選ぶ。理由が無ければ 1 回だけ問い返す | **Planner**（構造化出力 `PlanOutput`） | 候補はそのテーマの残りの実験だけ（学級の許可・やり終えた実験を除く）。答え（`answers.py`）は渡さない |
| 保留の理由を読み、同じ実験で直すか別の実験へ切り替えるかを提案する | **Replanner**（`ReplanOutput`） | 候補外への切り替えは測り直しに。測り直しの助言が**その実験の条件の値**（放す高さ・はじく強さ・水の量 など）を変えさせていたら、理由を返して作り直させる（条件を変えると別の実験になるため） |
| 結果を読み、次に確かめる実験と次の予想の問いかけを選ぶ（食い違って理由がまだなら「先にふり返り」） | **NextStep**（`NextOutput`、`POST /api/next`） | 問いかけに結果の言葉が混じれば差し替え。残りが無ければモデルを呼ばない |
| 学級の要約を**ツールで読み**、先生に 3 行・見に行く順・選べる手を伝える | **ClassAgent**（ツール `get_class_snapshot` / `get_student_timeline`、`POST /api/class/{code}/insight`） | ツールは読み取り専用で、予想の本文と名前は渡さない（テーマ・段階・出来事の種類も列挙だけ）。呼べるツール・回数（4 回、一人ずつは 3 人まで）・番号を `before_tool_callback` で制限。**人数はモデルに書かせず**、〔テーマ・状態〕のキーをサーバが「音の高さで保留 2 人」のように何の人数かまで埋める（別のテーマの名前に別のテーマの数を付けた行は落とす）。「止める」を勧める文は落とす |
| 測定後のふり返り | **Tutor**（ラボ先生） | 説明は、生徒が自分の考えを書いて判定が出ているときだけ。閉じている間の説明の言い回しは問い返しに差し替え |
| 安全（禁止動作・メモ内の指示・答えの要求） | 決定論の Policy（`policy.py`） | **モデルを呼ぶ前に**判定。却下は理由 3 つ＋代替 |
| 測定の検査・判定文・停止 | 端末内の計算とテンプレート | LLM は関与しない |

### 統制層 `PolicyPlugin`（ADK `BasePlugin`、`server/agent/policy_plugin.py`）

- `before_run_callback` — 先生が学級を止めていればエージェントを走らせない
- `before_model_callback` — ① **Model Armor**（us-central1 のテンプレート）で生徒の文を 1 回だけ検査し、検知したらモデルを呼ばない ② 回数上限（Planner 5 回 / 実験、Replanner・次の一手 3 回 / 記録、Tutor 10 往復）③ 温度・出力長・思考量を強制
- `before_tool_callback` — 許可したツールだけ、回数の上限まで、学級にいる番号だけ。断るときはツールを走らせずに理由を返す
- `after_model_callback` — 候補外の実験、結果の言葉、条件を変えさせる助言、説明の漏えい、停止の勧めを検査する

**検査に落ちた出力は、理由を添えて 1 回だけモデルに作り直させる**（自己修正。Planner・Replanner・次の一手。見立ては差し替えだけ）。作り直しも落ちたら統制層が差し替える。どちらになったかは応答の `trail`（判断の跡）に残り、生徒の画面・教員画面・Cloud Trace（`phonelab.self_correct` スパン）で同じ段が見える。生徒の文はスパンに入れない。記録の要約には、ラボ先生を呼んだトレース id を段の名前（計画・再計画・次の一手・会話）つきで最大 24 件（呼び出しの上限の合計 21 より多い）と、測定ごとの 2 つの値・落ちた検査・生データのハッシュを載せるので、先生は「どの測定で何に落ちて、ラボ先生が何を提案したか」を 1 画面でたどれる。

### 数字で見る（[`docs/eval.md`](docs/eval.md)、本物の Gemini と Model Armor で 10/2 に 3 回・10/12 に 1 回計測。10/12 は 10/9 のセキュリティの直しと 10/12 に足した実験を入れたあと。回ごとの揺れは eval.md の 10 節）

|---|---|
| 予想の変数・向き・実験の選択 | **30 / 30** ずつ（中学の 3 テーマ・7 実験、予想 34 件。問い返しのあとの計画で。10/12）。端末の規則（キーワード）は 27・28・28 / 30。規則が外したのは「消しゴムを足すと…」（重さ）と英語の予想 |

| 計画が出るまで（問い返しのあとの 2 回目を含む） | 中央値 1.3〜2.6 秒、95% 2.8〜4.5 秒（4 回の実行。10/12 は 1.3 秒・3.1 秒） |
| 注入・禁止動作 20 件 | Model Armor で 4、決定論のパターンで 6、残り 10 件はモデルに届いたが **最終出力に、生徒が書いていない結果の言葉や答えが出たのは 0 件** |

| 測定コードの正確さ（合成の信号。[`docs/eval/measure-bench.json`](docs/eval/measure-bench.json)） | 答えの分かっている信号を端末と同じ解析・検査に通した（各 40 回）。きれいな音・教室ほどの雑音・倍音の無い音・80〜100 Hz の低い音で、誤って通したもの 0、誤差の中央値 0.04〜0.22%。雑音が大きい・音割れ・隣の班の音が混ざると全部保留。振り子は誤差の中央値 0.004〜0.018 m/s。**このベンチマークで弱点を見つけて直した**（同じ信号・同じ数え方で 10/9 の版と比べると、基本の音が弱いと 1 オクターブ上を答えて検査も通っていた: 倍音の形を変えた 3 場面で 40/40・38/40・37/40 → すべて 0。1 オクターブ下か決められない音は保留にする。振り子の雑音の山を最下点と取り違えていた: 20/37 → 7/36。倍音の無い音を余計に保留していた: 3/40 → 0/40）。音に入っている成分の山を推定した基本の倍音で説明できるか（調和性）を確かめ、説明できない音は保留にする。音を出す前（最初の 0.5 秒）から鳴っていた背景（電源のうなり・声・ざわめき）は覚えて数えない。ただし弱い本当の基本が残りうる位置（推定の 1/2・1/3…）の背景は、はじいた音が弱まっていくあいだずっと大きさが変わらないときだけ背景とみなし、決められなければ保留する。倍音 8 つまで・倍音のずれ・雑音・減衰・和音を含む 24,500 通り（1 フレームでふるい、候補を 5 秒の信号で確認）で、誤って通る・比べた向きが逆になるは **0 件・0 件**（10/9 の版は 1 フレームのふるいで 6,215 件・8,306 件）。和音はほぼ全部を保留する。弱い基本と同じ高さに背景が重なる 1,920 通りでは、誤って通るのは 16 件（10/9 の版は 1,147 件）。4 回はじいた音にうなり（50/60 Hz、−25〜−35 dB）が重なると 40 個の高さのうち 0〜8 個を保留する（安全側）。限界: 基本の音が −38 dB より弱い（ほぼ無い）と、いちばん強い倍音を基本と取り違えうる。背景が弱い基本とまったく同じ高さで、基本より強いと見分けられない。実機の代わりではない（マイクの特性・部屋の反響は入らない） |
| 31 人ぶんの負荷を本番で同時に（[`docs/load-test.md`](docs/load-test.md)、模擬クライアント） | 入場・計画（Gemini）・記録の送信 186 回・測定中の確認 186 回・教員画面・停止がすべて 200。計画は 31 本同時で中央値 3.6 秒。停止の API が応えてから 31 本すべてが停止を受け取るまで中央値 1.5 秒・最大 2.1 秒（実機の端末ではない） |
| 費用（31 人 × 3 実験・50 分） | Gemini は ふだん 約 30 円・混雑 約 60 円・回数の枠を使い切った場合 約 120 円（どれも 1 回あたりの実測の平均トークン × 想定の回数 × 1 ドル 150 円の試算。請求の実績ではなく、文が長くなれば増える）。Model Armor・Firestore・Cloud Run を足して、無料枠を使わない場合 約 47・89・162 円 |

Model Armor は日本語の言い換えの多くを拾わなかった（英語と「開発者モード」は拾った）。だから三層（Model Armor → 決定論のパターン → 構造化出力と出力の検査）で守る。Planner にツールで候補を読ませる方式（`PHONELAB_PLANNER_TOOLS=1`）も比べたが、正答率は同じで 0.9 秒遅く、トークンが 2.4 倍だったので既定はオフ。

### セキュリティとガバナンス（10/9 に Codex のセキュリティレビュー `docs/reviews/2026-10-09-codex-security.md` を受けて強化）

| 守るもの | どう守るか |
|---|---|
| **最小権限** | Cloud Run は専用のサービスアカウント `phonelab-runtime` で動く。付けた役割は Gemini・Firestore・Model Armor・Trace の書き込みの 4 つだけ（Editor は外した）。デモの PIN とセッションの署名鍵は Secret Manager に置き、その秘密だけを読める。手順は `infra/runtime-identity.sh`（何度流しても同じ結果） |
| **学級の統制から外れない** | 本番（`PHONELAB_REQUIRE_CLASS=1`）では、ラボ先生（AI）を呼べるのは学級の生徒（合言葉が合う）だけ。停止・センサーの許可・家でやる実験の許可は、計画・再計画・次の一手・会話のすべての入口で効く。学級に入っていない端末は端末内の決まりごとで動く |
| **プロンプトインジェクション** | 端末から来る自由文はすべて Model Armor に通す（予想・前回の問い返し・会話の発言・考え・履歴）。**Model Armor が検査できなかったときは、その文をモデルに渡さず**決まりごとで進める（fail-closed）。決定論のパターンと、出口の検査（候補外・結果の言葉・条件を変える助言・**危ない動作の勧め**・説明の漏えい）は別にかかる |
| **実行の上限** | 回数の枠は Firestore のトランザクションで、モデルの前に取る（記録ごと: 計画 5・次の一手 3・再計画 3・会話 10。生徒ごと 1 日: 40・20・20・100）。自己修正のやり直しの直前にも枠と停止を確かめる |
| **停止** | 先生の「全端末の測定を止める」は 2 秒ごとの確認で届く（31 本の模擬クライアントで中央値 1.5 秒）。学級の状態を 3 回続けて確かめられない端末は、先生の停止が届くか分からないので測定に進ませない |
| **先生の認証** | PIN は scrypt で保存。間違いは Firestore で数える（接続元ごと 10 回・学級全体 30 回 / 10 分。インスタンスが何台でも同じ数）。入った先生にはサーバの秘密鍵で署名したセッションの印（8 時間まで） |
| **監査** | 先生の操作（止めた・解除した・許可を変えた・合言葉をリセット・見立てを聞いた・PIN のロック）を追記だけで残し、教員画面に出す。エージェントの判断は「判断の跡」と Cloud Trace（段の名前つきのトレース id） |
| **Web** | 厳しい CSP（スクリプトは自分のオリジンだけ）・フレーム禁止・nosniff・HSTS・Permissions-Policy（位置情報は禁止）・API は no-store。共用端末は「記録と合言葉を消す」で次の人に渡す |
| **供給網** | `npm ci`・`uv sync --frozen`、ベースイメージと uv は digest で固定、コンテナは非 root |

### 限界（正直に）

- **測定の判定は端末**。サーバは特徴量の要約を受け取るだけで、再検証はしない（記録の状態は端末の申告。サーバは時刻の未来を拒み、説明の解禁は記録の要約で決める）。「署名」は端末で計算したハッシュ（Cloud KMS は設計だけ）
- **出席番号は、最初に入った端末が持つ**（名簿の事前配布はしない）。同じ番号の同時入場はトランザクションで 1 台だけ、学級の番号は 60 まで。取り違えは先生が教員画面でリセットする
- **接続元ごとの回数制限（計画・会話の 10 分あたり）はインスタンスのメモリ**。エージェントの回数の枠・PIN の間違いは Firestore で数えるので、台数に左右されない
- **実機での閾値**（速さ 0.15 m/s、音の高さ 3%、倍音の整合）は暫定。実機 3 機種の検証は `docs/device-check.md` の手順で進めている

## Google Cloud の使い方

| サービス | 用途 |
|---|---|
| **Cloud Run**（asia-northeast1、min-instances 0） | FastAPI + ADK と Web アプリの配信。`gcloud run deploy --source`（Cloud Build） |
| **Vertex AI — Gemini 3.5 Flash-Lite** | 5 つのエージェントすべて（Planner・Replanner・NextStep・ClassAgent は構造化出力、Tutor は文章）。thinking low。混み合い（429）は短く 2 回までやり直す。計画が出るまで中央値 1.3〜2.6 秒（問い返しの 2 回目を含む。4 回の実行）。3.8 Flash は 25〜50 秒かかる時間帯があり、生徒を待たせるので不採用 |
| **Agent Development Kit 2.8** | `LlmAgent` × 5、`FunctionTool` × 2（学級の見立て）、構造化出力とツールの併用、`Runner`、`BasePlugin`（統制層）、`InMemorySessionService` |
| **Model Armor**（テンプレート `phonelab-student`、us-central1） | 生徒の文の注入・脱獄・有害表現の検査（Planner とチャットの前）。東京リージョンには多言語の検出が無いため us-central1 |
| **Firestore**（native） | 学級 `classes/{code}`、生徒 `students/{no}`（いまの記録の要約）、`records/{id}`（履歴）。クライアント SDK は使わず API 経由だけ |
| **Cloud Trace**（Telemetry API、OTLP） | 1 リクエスト = 1 トレース（計画・再計画・次の一手・会話・見立て）。`phonelab.plan → invoke_agent → phonelab.model_armor → call_llm → phonelab.policy → phonelab.self_correct`。トレース id は段の名前（計画・再計画・次の一手・会話）つきで記録に残り、教員画面から開ける |

費用の考え方: サーバが数える回数の枠は 1 実験あたり 計画 5・次の一手 3・再計画 3・会話 10（作り直しも枠に入る）。授業 1 回（31 人 × 3 実験）の Gemini は ふだん 約 30 円、枠を使い切った場合 約 120 円の試算（[`docs/eval.md`](docs/eval.md) 9 節。Cloud Run・Model Armor・Firestore 込みの見積もりも同じ節）。接続元ごとにレート制限（plan / chat 30 回 / 10 分、記録 120 回 / 10 分、PIN 10 回 / 10 分）。Cloud Run はアイドル課金なし。

## ローカルで動かす

```bash
# サーバ（Python 3.12、uv）
cd app
PHONELAB_CLASS_STORE=memory PHONELAB_DEMO_PIN=1234 \
GOOGLE_GENAI_USE_VERTEXAI=true GOOGLE_CLOUD_PROJECT=<project> GOOGLE_CLOUD_LOCATION=global \
uv run uvicorn server.main:app --port 8080
uv run pytest -q            # 144 件（Gemini は呼ばない。FakeLlm / ScriptedLlm）
uv run python -m scripts.eval_agent   # 評価（本物の Gemini・Model Armor を呼ぶ。env は先頭の docstring）

# Web（Vite。/api は 8080 へプロキシ）
cd app/web
npm ci && npm run dev -- --port 5179
npx vitest run              # 82 件
```

環境変数: `PHONELAB_MODEL` / `PHONELAB_CHAT_MODEL`（既定 `gemini-3.5-flash-lite`）、`PHONELAB_CLASS_STORE`（`memory` | `firestore`。Cloud Run 上は既定で firestore）、`PHONELAB_DEMO_PIN`（起動時に学級 `DEMO-2026` を作る）、`PHONELAB_TRACE_TO_CLOUD=1`（Cloud Trace へ送る）、`PHONELAB_MODEL_ARMOR_TEMPLATE`（`projects/.../locations/us-central1/templates/...`、無ければ使わない）、`PHONELAB_DEMO_SAMPLES=1`（見本の記録 D-01〜D-06 を起動時に置く）、`PHONELAB_PLANNER_TOOLS=1`（Planner にツールで候補を読ませる。既定オフ）。
