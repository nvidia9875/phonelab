## Phase 2: 審査基準への対応
### 軸1: 課題の新規性と解決策の有効性
- [ ] 「多くの人が抱えながら未解決の課題」を明確に定義できている
- [ ] 対象ユーザー像が具体的（ペルソナレベル）
- [ ] ソリューションが課題の核心に効いている説明ができる

### 軸2: 自律性・エージェントらしさ
- [ ] **単純な自動化を超えている**（分岐したワークフローではなく、状況判断で行動を選ぶ）
- [ ] エージェントが自律的にツールを選択・実行し、結果を評価してリトライ/軌道修正する
- [ ] **可観測性**: トレース／ログ／実行履歴の可視化を実装（Cloud Trace / Cloud Logging / 評価ダッシュボード等）
- [ ] **セキュリティ**: プロンプトインジェクション対策、権限の最小化、機微情報の扱い
- [ ] **管理・制御**: Human-in-the-loop の承認ゲート、停止・ロールバック、実行上限（ループ・コスト）
- [ ] これらをデモ動画とアーキテクチャ図で**目に見える形**にしている

### 軸3: 実装品質と拡張性
- [ ] 主要機能がモックでなく実装されている
- [ ] 拡張性・運用性を考えた構成（責務分離、IaC、CI など）
- [ ] **費用対効果**を語れる（アイドル時ゼロ課金、モデルの使い分け、キャッシュ等）
