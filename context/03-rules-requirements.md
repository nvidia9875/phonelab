# 03. ルール・参加条件・開発要件

## 参加資格

- **日本国内に居住する 18 歳以上の個人、または個人により構成されるチーム**。
- 以下は参加不可:
  - 政府機関の職員（**非常勤・兼業（フリーランス）でも該当し参加不可**）
  - 企業の意向によって当該企業の代表として選出された個人
  - スポンサーおよび主催者の従業員、その関係者および家族
  - 本ハッカソンの企画、運営に直接関与する者
  - その他、主催者が不適切と判断した者
- Google Cloud Innovators プログラムへの参加は**不要**。

## 参加形態

- 個人でもチームでも可。
- チームの場合、**代表者・メンバー全員がそれぞれ参加登録（エントリー）必要**。
- 代表者がダッシュボードでプロジェクトを作成し、エントリー済みメンバーを招待する流れ。
- チームビルディング希望者は Discord へ（専用チャンネルあり）: https://discord.gg/cvA2Z3yny4
- **複数プロジェクトへの参加可**。チーム参加しながら個人で別プロジェクト提出も可。審査上の不利は無し。
- チームメンバーの追加・脱退は 2026/10/15 23:59 まで可能。

## エントリー手順

1. 公式ページの「申し込む」ボタンから **Zenn アカウントでログインしてエントリー**
2. ダッシュボードに表示される **参加者情報フォーム（Googleフォーム）** に氏名・所属等を入力 → **参加登録完了**
3. 参加登録が完了するとプロジェクトを作成できるようになる
4. Google アカウントは **企業のものより個人アカウント推奨**（セキュリティポリシーで Gemini 等に接続できない場合があるため）

## 🔴 開発プロジェクト条件（必須要件）

提出プロジェクトは以下の必須条件を**すべて**満たす必要がある。

### 必須1: Google Cloud アプリケーション実行プロダクトの利用（いずれか1つ以上）

- App Engine
- Compute Engine
- Google Kubernetes Engine（GKE）
- Cloud Run
- Cloud Run functions（旧 Cloud Functions）
- Cloud TPU / GPU

> FAQ 補足:
> - **Cloud Functions for Firebase** → 条件を満たす ✅
> - **Firebase App Hosting** → 条件を満たす ✅
> - **Firebase Extension のみ** → 条件を**満たさない** ❌
> - ローカル環境で動くだけでは不可。**Google Cloud へのデプロイが必要**。
> - dev 環境での稼働で問題なし（動作確認さえできれば良い）。

### 必須2: Google Cloud AI 技術の利用（いずれか1つ以上）

- Gemini Enterprise Agent Platform（**旧称 Vertex AI**。Model Garden、Vector Search などを含む）
- Gemini API（Gemini Enterprise Agent Platform 経由での利用を推奨）
- Gemma
- Nano Banana
- Agent Development Kit（ADK）
- Speech-to-Text / Text-to-Speech API
- Vision AI
- Natural Language AI
- Translation AI

> FAQ 補足:
> - **Gemini API を AI Studio から直接利用**でも条件を満たす ✅（ただし必須1は別途必要）
> - **Firebase 経由の Gemini API 利用**でも条件を満たす ✅

## 📋 提出物

ダッシュボードで作成したプロジェクトに以下を登録して提出する。

1. **プロジェクトの GitHub 公開リポジトリの URL**
2. **プロジェクトをデプロイした URL**
   - 認証が必要な場合は**テストアカウントを作成**し、「動作確認の方法」項目に認証情報を記入
   - **ソーシャルログインやメール受信が必須のログイン方法は避ける**（審査が難しいため）
   - そのテストアカウントから閲覧できる**サンプルデータも作成**すること。審査員はテストアカウント＋サンプルデータをベースに審査する
3. **プロジェクトの説明**
   - 対象とするユーザー像と課題、課題へのソリューションと特徴をまとめた説明文
   - **システムアーキテクチャ図の画像**
   - **3分程度のデモ動画**（自作し **YouTube に公開**、URL を登録）
4. **Zenn 記事（任意）**: 投稿する場合はカテゴリ **「Idea」** で公開し、URL を登録

### 公開範囲

- 提出締切後、提出済みプロジェクトのページ（説明・アーキテクチャ図・デモ動画など）が**一般公開**される。
- **GitHub リポジトリの URL とデプロイ URL は審査にのみ使用**され、プロジェクトページには公開されない。
- 各審査はフェーズに応じて段階的に評価され、1次審査から全作品の全提出物を精査するとは限らない。
  → **最初の数十秒・説明文冒頭・アーキテクチャ図のインパクトが重要**。

### ネイティブアプリの場合（FAQ）

- Web / ネイティブどちらでも可。ただし必須1（Google Cloud 実行プロダクト）は満たす必要がある。
- デプロイURLには**可能な限り Web 版を公開してその URL** を記載。Web で難しい機能は未搭載でも可。
- Web 版の作成が困難な場合は、ネイティブアプリである旨と事情を説明した GitHub 公開ページ（README など）の URL を記載 → 審査時の申し送り事項として管理される。
- 審査員はリモート審査のため実機確認が難しく、**デモ動画中心の審査**になる（モバイルならではの体験も可能な限り考慮）。

## 🗂 GitHub リポジトリについて

- **公開状態**にすること。
- **提出時点の状態を 12月1日まで保つ**こと。
- 提出後も開発を継続したい場合は、**提出締切以前に作成したタグを GitHub へプッシュし、提出フォームにはそのタグの URL を記載**する（FAQ ではタグまたはブランチと表現）。
- 審査期間である 12月1日までは、**デプロイした上で動作確認できる状態**にしておくこと。
- コードの公開範囲: 可能な範囲でよい。ただし **どの部分を開発したのか、パッケージ化している部分はどこかなどの構成説明を必ず加える**こと。**主要機能がモックではなく実際に実装されていることが分かる程度**に公開する。

## 🔍 審査基準（3軸）

### 1. 課題の新規性と解決策の有効性
> 多くの人が抱えながらも、いまだ解決策が与えられていない課題を発見できているか。また、提案されたソリューションがその課題の核心に効果的に対処し、実質的な価値をもたらしているかを評価します。

### 2. 自律性・エージェントらしさ
> 単純な自動化を超え、状況を判断しながら自律的に行動するエージェントとして設計されているか。さらに、その自律性が適切に管理・制御されており、可観測性やセキュリティへの配慮を持った、信頼できる動作をするかを評価します。

### 3. 実装品質と拡張性
> アイデアをどれだけ高い品質で実現できているか。必要なツールを適切に活用し、拡張性・運用性・費用対効果を考慮した、実用に耐えるソリューションを構築できているかを評価します。

※ 奨励賞は「3つの審査基準のうちいずれかが秀でており、今後の発展が期待できるプロジェクト」に贈られる（最終ピッチ進出プロジェクト以外から選出）。

## ⚠️ 禁止事項・注意事項

- ❌ **ハッカソン開始時点（2026/8/20）で一定進捗していたプロジェクトの提出は不可**（公平性の観点。「ハッカソンはあくまで競技」）。
- ❌ **提出後に記事・リポジトリ・動画を修正しない**（提出時点の成果物を評価するため）。
- ❌ 提出締切から 12月1日（最終審査）までの間、提出リポジトリに修正を加えない（継続開発はタグ／ブランチで）。
- ⚠️ Google Cloud の費用は**自己負担**（クーポン超過分は課金される）。
- ⚠️ 参加取り消しの操作は無い。提出しないまま締切を迎えて問題なし、ペナルティ無し。
- ⚠️ 審査結果は1次審査後・2次審査後にそれぞれ通過・落選が全員に連絡される（落選連絡の省略は不可）。
